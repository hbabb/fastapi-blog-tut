# Lesson 2: Templates - Return Dynamic HTML

## Different from the Tutorial

The tutorial keeps `templates/` and `static/` in the project root, next to `main.py`. Since all of my app code lives under `src/`, I moved both folders there:

```shell
src
├── app.py
├── core
├── posts
├── static
│   ├── css
│   ├── icons
│   ├── js
│   ├── profile_pics
│   └── site.webmanifest
└── templates
    ├── home.html
    └── layout.html
```

That move meant one code change. The tutorial uses relative paths, `directory="static"` and `directory="templates"`, which are looked up from whatever folder the app is started from. With my layout those wouldn't be found, so I build the paths from `app.py`'s own location using `Path(__file__)`. That way it works whether I run it from `just`, PyCharm, or `uv run`.

The tutorial repo also has `layout_finished.html` and `home_finished.html` in the root. Those are just the plain HTML design before it's converted to Jinja templates. The app never reads them, so I left them out.

## Learned

- **`url_for('static', path='...')`**: `'static'` isn't a folder name. It's the `name="static"` given to the mount in `app.py`. `path` is the file's location inside the static folder. It renders to a real URL like `/static/profile_pics/default.jpg`.

- **Order in `app.py`**: constants after imports, then setup, then `app = FastAPI()`, then `app.mount(...)` and the templates object, then routes. `mount` has to come after the app exists, because it's a method on the app.

- **Stacked route decorators**: putting `@app.get("/")` and `@app.get("/posts")` on one function serves the same page at two URLs. Each gets its own `name` so templates can link to either one with `url_for()`.

- **Favicons are cached separately.** Browsers hold onto favicons harder than anything else on the page. A normal refresh often won't pick up a new one.

## Struggled With (and What Helped)

- **PyCharm flagging `url_for` in `home.html`.** It reported "Cannot resolve directory" and wanted to create one. The app worked fine. PyCharm was reading the whole `src="{{ url_for(...) }}"` value as a literal file path because it didn't know the file was a Jinja template. Claude AI helped me read the warning and find the setting: Template Languages → Jinja2.

- **The favicon not showing.** The profile picture loaded, so the static mount was fine. Opening the favicon URL directly proved the file was being served. It was the browser's favicon cache.
