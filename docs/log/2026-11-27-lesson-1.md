## Different from the Tutorial

I like my projects to have structure from the start. `main.py` is the entry point, and it hands off to `src/app.py`. Everything else lives under a `src` directory, organized by purpose:

```shell
 .
├──  docs
│   └──  log
│       └──  2026-11-27-lesson-1.md
├──  justfile
├──  LICENSE
├──  main.py
├──  pyproject.toml
├── 󰂺 README.md
├── 󰣞 src
│   ├──  __init__.py
│   ├──  app.py
│   ├──  core
│   │   ├──  __init__.py
│   │   ├──  config.py
│   │   ├──  logging.py
│   │   └──  project.py
│   └──  posts
│       ├──  __init__.py
│       └──  data.py
└──  uv.lock
```

I added logging with `structlog`, a Python library for structured logging, along with `Rich` to make the log output easier to read in the terminal during development.

`project.py` reads the project name and version from `pyproject.toml`. I use them in the health check, and I can use them anywhere else I need them. Bumping the version means updating one place.

I also moved the posts data out of the main app file and into `src/posts/data.py`. The tutorial keeps it in `main.py`, which makes sense for proving out a concept quickly. My preference is to keep data separate from the code that uses it, so `app.py` stays clean. There's a practical upside too: when the course replaces these dictionaries with a real database, there should be less to refactor.

## Struggled With (and What Helped)

- **A duplicate PyCharm module.** PyCharm crashed, so I opened the project in IntelliJ, and that left the project with an extra module that broke how the environment was picked up. Claude AI helped me track down the cause and work through the fix.

- **Bringing over structure from a production project.** I'm also working on a full production FastAPI project, and I wanted to reuse what I've learned there. Repeating those patterns here helps me understand them more deeply. Translating them wasn't always straightforward, though. FastAPI doesn't dictate how a project should be set up. That flexibility is great, but it's a double-edged sword: every structural decision is mine to make.

## Achievements

- It might be a small thing, but I figured out how to use my setup to read the project name from `pyproject.toml` and include it in the "Hello World!" route's response using an f-string.
```python
@app.get("/", tags=["home"])
def home():
    return {"message": f"Hello World! from {PROJECT_NAME}!"}
```
